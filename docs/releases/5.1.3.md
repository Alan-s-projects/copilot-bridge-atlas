# Copilot Bridge Atlas 5.1.3

Grok compaction requests with no available tools now omit `tool_choice` and
`parallel_tool_calls` before forwarding to GitHub Copilot. Codex can send
`tools: []` with `tool_choice: "auto"` during local compaction; xAI/Grok rejects
that combination. Requests with tools, including tools declared inside input,
retain their tool-selection settings.

Atlas's Info and failure logs now record safe request-shape categories:
whether the outbound tool list is absent, empty, or nonempty; the incoming and
outbound tool-choice kinds; and whether parallel tool calls were specified.
Matching Usage history errors retain the same categories. Tool names, prompt
contents, and raw upstream response bodies are not logged.

This addresses one demonstrated class of Grok compaction HTTP 400. The earlier
generic `Bad Request` responses alone do not establish that it caused every
observed failure. There is no database migration or UI change. Install
`Copilot-Bridge-Atlas-5.1.3-Windows-x64.msi` and verify it with the matching
`.sha256` file. The unsigned per-user installer is not installed automatically
by publishing this release.
