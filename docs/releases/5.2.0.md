# Copilot Bridge Atlas 5.2.0

Usage → Request Logs now opens a centered error detail view when a failed
status is selected. It shows the logged status, the upstream HTTP status,
failure stage, request ID, model, and bounded request/response headers and
bodies. One X closes the view. A failure event inside an HTTP 200 Responses
stream is recorded with its `response.failed` event body under the logged 502
status, so the actual failure can be inspected even when it arrives after a
long stream.

New failed requests save up to 32 KiB each of the outbound request and upstream
response body, with the first and last 16 KiB retained for larger bodies.
Common credential-bearing headers are redacted. The snapshots are stored in Atlas's
database and written as escaped, correlated lines to the local file log.
**Request or response bodies may contain conversation content or echoed
credentials.** Treat logs and database backups as sensitive. Older request
rows cannot recover bodies that were not recorded.

First-party comments, logs, and error messages are now in English. A new
Windows release pipeline builds the MSI and SHA256 file from an `atlas-*` tag
on the `atlas` branch and publishes them with run and source metadata at the
start of the release description.

Install `Copilot-Bridge-Atlas-5.2.0-Windows-x64.msi` and verify it with the
matching `.sha256` file. The unsigned per-user installer is not installed
automatically when the release is published.
