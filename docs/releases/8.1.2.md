# Copilot Bridge Atlas 8.1.2

## Recover Codex history after switching Copilot accounts

- Retry native Responses requests once when Copilot rejects saved history with HTTP 400 or 401 and the exact message `input item does not belong to this connection` or `input item ID does not belong to this connection`.
- Remove unavailable reasoning and upstream item IDs from the retry while preserving messages, images, tool arguments/results, and tool call/result links.
- Keep the selected account and model fixed during recovery. Healthy requests and saved Codex transcripts remain unchanged.

After updating and restarting Atlas, retry the affected Codex chat. Recovery can add one upstream attempt per affected turn and cannot preserve hidden reasoning that the new account cannot use.

This release does not reconstruct encrypted compaction or linked/opaque history. Those requests retain their original error rather than silently losing earlier context. Recovery also does not cover failures inside an already-started response stream or native WebSocket replay.

## Validation

- The fix passed the full Windows Rust test suite and a live two-turn replay of affected Codex history.
- Both encrypted reasoning and upstream item IDs had to be removed for that history to succeed. Its original transcript was unchanged.
- The release workflow runs frontend, script, and Rust checks and builds both platform packages before publication.
