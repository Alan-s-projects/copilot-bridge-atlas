# Claude context-overflow recovery validation — Atlas 7.1.4

Date: 2026-10-25. Host: macOS Intel. Client: installed Claude Code 2.1.308
(the executable bundled with Claude Desktop). Client model: `claude-fable-5`;
Atlas mapping: `gpt-6-astra`.

## Reproduction and acceptance criteria

The reported failure was an HTTP 400 with this Copilot message:

> Your input exceeds the context window of this model. Please adjust your input and try again.

Atlas previously wrapped it in its generic Responses proxy diagnostic. The
client stopped below its presumed 1M context window's automatic-compaction
threshold. Acceptance requires a real client compaction event and successful
continuation, not just matching the text of a proposed error response.

## Tests performed

### Deterministic end-to-end tests

The ignored `context_overflow_real_claude` tests launch the real client against
Atlas's real Messages router, request conversion, internal Responses handler,
and a local Copilot HTTP fixture. Every test uses an isolated Claude home and
fresh conversation; no existing sessions or client settings are modified.
No compaction-window or percentage override is set.

The fixture keeps rejecting the original history until the client requests a
summary. It does not merely fail once and then allow an unchanged retry.

| Case | Result |
| --- | --- |
| Previous Atlas error wording | Client fails; no `compact_boundary` and no summary request |
| Normalized HTTP 400 | Automatic `compact_boundary`, summary request, successful continuation |
| Normalized streamed `response.failed` | Automatic `compact_boundary`, summary request, successful continuation |

The streaming case also exercises Claude Code's fallback to a non-streaming
request after an SSE failure. Atlas returns the same recognizable error when
buffering that upstream failure.

### Live Copilot recovery test

The separate ignored `context_overflow_live_claude_compacts_and_retries` test
uses a disposable authentication copy and a small synthetic conversation. A
loopback fault injector returns the original context-overflow rejection for the
second turn. All successful model responses are generated by actual GPT-6 Astra
through Copilot: the initial reply, the compaction summary, and the resumed
answer.

Observed:

- Four requests at the local upstream boundary: initial reply, injected rejection,
  summarization, continuation; every request targets `gpt-6-astra`.
- Claude Code reports `compact_metadata.trigger: "auto"`.
- Client-reported context before/after compaction: **3,080 → 1,759 tokens**.
- Summary duration reported by the client: **33,416 ms**.
- Final result: `is_error: false`, `terminal_reason: "completed"`, and
  `ATLAS_CONTEXT_RECOVERED`, the original conversation's codeword.
- Test completed successfully in **42.23 seconds**.

### Automated regression checks

- HTTP overflow envelopes tested on both Copilot Chat Completions and Responses
  transports, for streaming and non-streaming Claude clients.
- Numeric overflow messages preserve valid provider-supplied counts. Missing or
  malformed counts produce only `prompt is too long`.
- SSE `response.failed`, `error`, and failed-status terminal events tested for
  streaming and buffered clients.
- Unrelated HTTP errors and successful context/output-limit stops are not
  reclassified as input overflow.
- Full Rust suite passed; opt-in real-client/live tests run separately.
- Frontend: **54 test files / 297 tests passed**, TypeScript checks passed, and
  the production renderer built successfully.
- Python validation scripts: **25 tests passed**.

## Limitations

This is controlled fault-injection validation, not an organic exhaustion test at
Copilot's actual context limit. It proves that the observed error can trigger
Claude Code's real recovery using the Atlas-only fix, including real upstream
summarization. It does not establish GPT-6 Astra's precise input limit or guarantee
that a conversation already too large to summarize can be recovered.

No Claude settings, model mappings, token accounting, or Codex behavior were
changed. The running installed Atlas app and the user's original failed session
were not modified by these tests.
